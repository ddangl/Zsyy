# 新区域打卡统计（Docker 衍生版）部署说明

本应用是「打卡数据整理助手」的独立衍生版，与一区版（端口 45785）部署在同一台服务器上互不影响。代码在 `app2/` 目录内自包含（main.py / processor2.py / config2.py / static/）。

## 与一区版的区别

| 项目 | 一区版 | 本版 |
|---|---|---|
| 目录 | `app/` + 根目录 Dockerfile | `app2/`（自包含） |
| 端口 | 45785 | 45786 |
| 访问前缀 | `/daka` | `/daka2` |
| 登录 Cookie | `daka_auth` | `daka2_auth` |
| 上班时长 | 手填时间模糊解析 | 上/下班完整日期时间直接相减 |
| 分组 | 按楼栋/区域 | 白班 → 接班 → 值班 |
| 处理是否回写 Excel | 回写合并结果 | 纯过滤，不回写 |

## 数据格式（自动识别，两种都支持）

**新表单（2026-08-26 起）**，每日 Sheet 列：

| 列 | 说明 |
|---|---|
| 上班时间（24小时制）/ 下班时间（24小时制） | 完整日期时间，如 `2026-08-26 16:00` |
| 今日是白班还是16点接班 | `白班：（请补充工作地点手术室）：12` = 今日白班+房间；`16点接班` = 接班 |
| 明日工作地点手术室 | `白班（…）：19` = 明日房间；`16点接班`；`值班` |

**旧表单（2026-08-26 前）**：`上班时间`/`下班时间`、`工作地点（几号手术室）`（当日房间）、`是否4p副麻接班`。

## 统计规则

- 统计目标日 = 文件名第一天；从所有日期 Sheet 取「上班时间」在目标日的记录（跨日补卡自动归位）
- 同工号多条打卡取最新一条；未参与/工号为「无」的行不显示
- **表格列**（与一区版同款）：`姓名(工号) | 次日 | 下班时间 | 当日(灰)`
  - 新表单：次日 = 明日工作地点（房间/接班/值班），当日 = 今日房间（接班显示「接班」）
  - 旧表单：当日 = 工作地点，次日留空
- **分组（按明日安排）**：白班（按时长升序）→ 接班（明日 16 点接班，按下班时间）→ 值班（明日值班，放最后）
- **标色**：13.5h 浅红 / 14.5h 中红 / 15.5h 深红；接班组、值班组、以及当日为接班的人不变色
- 下班跨零点显示「次日HH:MM」
- 打了上班卡但下班时间缺失/非法：处理日志列出名单，用「修改表格」补填后重新处理

## 部署（与一区版同服务器）

### 前提

- 服务器已装 Docker（一区版已部署即满足）
- 内存：两个容器各跑一个 Chromium，建议总共 ≥ 4GB（不足可加 swap）

### 第一步：上传部署包

把 `daka2-web.zip` 上传到服务器 `/www/wwwroot/` 并解压（宝塔：文件 → 上传 → 解压），得到：

```
/www/wwwroot/daka2-web/
├── app2/
│   ├── main.py / processor2.py / config2.py / requirements.txt
│   ├── Dockerfile / docker-compose.yml / 部署说明.md
│   └── static/（index.html / login.html）
└── fonts/msyh.ttc      # Dockerfile 构建时需要的中文字体
```

### 第二步：构建并启动

宝塔终端执行：

```bash
cd /www/wwwroot/daka2-web
docker compose -f app2/docker-compose.yml up -d --build
```

首次构建约 5~10 分钟（下载 Chromium），镜像约 1.5GB。一区版容器不受影响。

### 第三步：设置密码（必须）

密码通过环境变量 `SITE_PASSWORD` 注入，**不写在代码里**：

```bash
cd /www/wwwroot/daka2-web/app2
cp .env.example .env
vi .env        # 把 SITE_PASSWORD 改成自己的密码
cd ..
docker compose -f app2/docker-compose.yml up -d
```

> 未设置密码时应用可以启动，但无法登录（登录接口会提示"站点未设置密码"）。

### 第四步：访问

```bash
http://服务器IP:45786/daka2/
```

直接 IP 访问需在宝塔「安全」和云服务商安全组放行 `45786/TCP`。

### 第五步（可选）：与一区版共用域名，按前缀分流

若两个版本挂在同一域名下，站点反向代理配置（Nginx 示例）：

```nginx
location /daka/ {
    proxy_pass http://127.0.0.1:45785;
    proxy_set_header Host $host;
}
location /daka2/ {
    proxy_pass http://127.0.0.1:45786;
    proxy_set_header Host $host;
}
```

两个版本的登录 Cookie（`daka_auth` / `daka2_auth`）相互独立，同域名下也不会互相顶掉登录态。

## 数据目录

- `app2/data/`：上传的打卡 Excel（容器内 /app/uploads），7 天自动清理
- `app2/output/`：处理生成的 PNG/HTML（容器内 /app/outputs），7 天自动清理

## 使用流程（与原版一致）

1. 打开 `http://IP:45786/daka2/`，输入密码登录
2. 选择 Excel（文件名格式 `YYYY-MM-DD至YYYY-MM-DD_打卡记录.xlsx`）→ 上传
3. 「开始处理」→ 预览并下载 `YYYYMMDD下班统计.png`
4. 数据有问题时「修改表格」：双击单元格编辑（时间格式 `2026-08-26 16:00` 或 `16:00`）、可新增行，保存后重新处理

## 常用运维命令

```bash
cd /www/wwwroot/daka2-web

docker compose -f app2/docker-compose.yml ps        # 运行状态
docker compose -f app2/docker-compose.yml logs -f   # 查看日志
docker compose -f app2/docker-compose.yml restart   # 重启
docker compose -f app2/docker-compose.yml down      # 停止
docker compose -f app2/docker-compose.yml up -d --build  # 改代码后重建
```

## 常见问题

| 问题 | 解决方案 |
|---|---|
| 45786 访问不了 | 宝塔安全 + 云安全组放行 45786/TCP |
| 构建失败（网络超时） | Dockerfile 已配国内 pip 源和 Chromium 淘宝镜像，重试即可 |
| Chromium 安装失败/内存不足 | 加 swap 或 compose 里加 `mem_limit: 2g` |
| 提示"下班时间缺失" | 有人打了上班卡没填下班时间，日志有名单，用「修改表格」补填 |
| 有人在表单里填错工号 | 如实显示；如需统一，用「修改表格」修正后重新处理 |
| 改了 config2.py（阈值/分组/模板） | `docker compose -f app2/docker-compose.yml up -d --build` 重建生效 |
